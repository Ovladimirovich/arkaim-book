# ARKAIM STUDIO SPEC — Спецификация Studio v2

## 1. Архитектура

Studio v2 — режиссёрская рабочая область фильма. Управление идёт через сцены:
каждая сцена имеет рабочую область (сессия), в которой собираются промпты,
утверждаются кадры и создаются видеоклипы.

Фильм = последовательность эпизодов (глав) → сцен → планов (шотов).
Порядок канонический (геном книги), ассеты лишь привязываются.

## 2. Фазы (по приоритету)

### 2.1. Фаза 0 — Дерево фильма
Проекция фильма из генома: эпизоды → сцены → планы.
Read-only, без генерации. Пока статусы кадров/клипов.

### 2.2. Фаза 1 — Continuity (связность)
Сравнение соседних сцен/планов: локация, свет, палитра, персонажи, стиль.
Нахождение расхождений, формирование решений режиссёра.

### 2.3. Фаза 2 — Применение переноса
Применение решений continuity между сценarиями: перенос визуальных параметров
из одной сцены в другую с сохранением согласованности.

## 3. Сущности

### 3.1. Сессия (StudioSession)
Рабочая область сцены: промпты, версия, обсуждение, статус.

### 3.2. Версия (StudioVersion)
Снимок состояния сессии: image_description, video_description, video_scenario.

### 3.3. Обсуждение/комментарии
Сообщения участников сессии.

## 4. Роуты и данные

- `GET /studio/film` — дерево фильма
- `GET /studio/scenes` — список доступных сцен
- `GET /studio/list` — список сессий
- `POST /studio/create` — создать сессию сцены
- `GET /studio/{session_id}` — детали сессии
- `POST /studio/{session_id}/versions` — создать версию
- `GET /studio/{session_id}/versions` — список версий
- `POST /studio/video-jobs` — создать задание на видео (mock по умолчанию)
- `GET /book/assets` — ассеты (кадры/видео)

## 5. Ограничения (критично)

### 5.1. Безопасность (обязательно)
Не генерировать контент без явного действия режиссёра. По умолчанию mock.

### 5.2. Хранение
Не создавать новых сущностей/таблиц без необходимости. Использовать `studio.db`.

### 5.3. Мода
Не запускать платные видеогенерации. Интерфейс + mock-путь.

## 6. Границы

- `SCENARIO_VERSION = "0.1.0"` — фиксирован, не расширять.
- `ADR_ARKAIM_MEDIA_BOUNDARY` — VideoScenario НЕ содержит execution-семантики.
- `ADR_MEDIA_PLAN_V0` — MediaPlan v0 не расширяется, `extra="forbid"`.
- Film Reel ≠ Final Cut: лента — навигационный слой, НЕ монтаж.

## 7. Тесты (всего)

Backend: pytest, ~100+ тестов. Frontend: vitest, ~100+ тестов.

## 8. Continuity (Фаза 1) — согласованность планов и сцен

**Что это.** Анализ связности соседних планов (внутри сцены), границ сцен
и соседних сцен эпизода. Поиск расхождений в локации, свете, палитре, стиле,
персонажах. Формирование выводов и решений режиссера.

**Где живёт код.**
- Логика (чистые функции): `core/CORE/studio/continuity.py` — `build_scene_snapshot`,
  `compare_shots`, `compare_scenes`, `find_applied_decision`, `apply_decisions`,
  `make_basis`, `make_apply_basis`.
- Хранение решений: `studio_continuity_decisions` в `studio.db`.
- Роуты: `runtime/core/routes/studio.py` — `/scenes/{scene_id}/continuity`,
  `/continuity/summary`, `POST/DELETE /continuity/decisions`,
  `/{session_id}/continuity/match-context`, `/{session_id}/continuity/apply`.
- UI: `arkaim-web/src/app/studio/continuity-panel.tsx` (карточка «1.1 · Связность»)
  + типы в `types.ts`.

**Статусы связей.** `unchecked` / `mismatch` / `consistent` / `waived`.
**Источники данных.** Genome (факты), VideoScenario (сценарий), FilmArtDirection
(правила фильма), VisualContext (опционально).

**Перенос ограничений.** Применённый перенос отображается на сцене-приёмнике
через `transfer {applied, stale, from_scene_id, note}`. Кнопка «Применить
перенос» создаёт решение continuity. Отмена — `DELETE`.

**API (реализовано).**
| Метод | Путь | Роль | Назначение |
|---|---|---|---|
| GET | `/studio/scenes/{scene_id}/continuity` | reader | Связность сцены |
| GET | `/studio/continuity/summary` | reader | Сводка по всем сценам |
| POST | `/studio/{session_id}/continuity/decisions` | editor/admin | Создать решение |
| DELETE | `/studio/{session_id}/continuity/decisions/{decision_id}` | editor/admin | Отменить решение |
| GET | `/studio/{session_id}/continuity/match-context` | reader | Контекст переноса |
| POST | `/studio/{session_id}/continuity/apply` | editor | Применить перенос |

**Тесты.** Backend: `test_studio_continuity.py` (36). Frontend: `studio-continuity.test.tsx` (8).

## 9. Continuity (Фаза 2) — применение переноса между сценариями

**Что это.** Механизм переноса визуальных параметров (свет, палитра, стиль,
персонажи) из одной сцены в другую с сохранением canonical-порядка.
Read-only анализ + применимое решение.

**Правила.** Переносится только согласованная часть (consistent/waived).
Устаревший перенос помечается `stale=true` при изменении art_direction_revision.
Применение сохраняет историю в `studio_continuity_decisions`.

**API (реализовано).** Те же роуты, что в Фазе 1 — `POST/DELETE /continuity/decisions`,
`/{session_id}/continuity/apply`, `/{session_id}/continuity/match-context`.

**Тесты.** Backend: `test_studio_continuity.py` (36, включая apply).
Frontend: `studio-continuity.test.tsx` (8, включая применение).

## 10. Story Reel (Фаза 3) — лента сцены

**Что это.** Режиссёрский просмотр «Эпизод → Сцена → План → Кадр → Клип»:
показывает порядок и материалы, но **не** собирает фильм. Никакого монтажа,
таймлайна, экспорта MP4, ffmpeg или платной видеогенерации.

**Область (scope).** `scene` — одна сцена (`scene_id`); `sequence` —
подмножество сцен одного эпизода (`scene_ids`, comma-список); `episode` — весь
эпизод (глава книги); `film` — весь фильм (все эпизоды, все сцены). Порядок
всегда **канонический** (геном → сцены, сценарий → планы): лента не
переупорядочивает сцены и не меняет порядок планов. Ассеты только привязываются.

**Где живёт код.**
- Логика (чистые функции): `core/CORE/studio/reel.py` —
  `frame_state`, `video_for_shot`, `clip_state`, `is_mock`; статусы
  `FRAME_*` и `CLIP_*`.
- Роут: `runtime/core/routes/studio.py` — `GET /studio/reel`
  (+ `_build_reel_data`, `_reel_link_summary`).
- UI: `arkaim-web/src/app/studio/story-reel.tsx` (карточка «4 · Лента сцены» в
  `page.tsx`; область ограничена выбранной сценой/проектным контекстом) и
  `arkaim-web/src/app/studio/film-reel.tsx` (карточка «Лента фильма
  (режиссёрский обзор)» — всегда видна, независимо от выбранной сессии).

**Лента фильма (Film Reel) ≠ Final Cut.** Верхняя карточка `film-reel.tsx`
показывает состояние **всего фильма** (все эпизоды → сцены → планы → кадры →
клипы) без привязки к выбранной Studio-сессии. Это навигационный/режиссёрский
слой: клик «Открыть в Studio» переводит к рабочей области сцены, где и
происходит утверждение кадров и создание клипов. Лента ничего не монтирует и не
собирает.

**Связь кадр → видео.** Кадр: `approved` (утверждён) / `none` (отсутствует) /
`needs_update` (требует обновления — итоговый промпт изменился). Видео: `none` /
`generating` / `failed` / `mock` / `ready` / `stale` (устарел — сменился
утверждённый кадр или `art_direction_revision`). Mock имеет приоритет над
`stale`, но причины устаревания показываются честно. Если утверждённый кадр есть
и клипа нет — кнопка «Создать видео из утверждённого кадра» использует штатный
`POST /studio/video-jobs` (по умолчанию `preferred_backend=mock` — без трат),
передавая `shot_id` и `image_asset_id`.

**Continuity на границах.** Между планами (`shots_within_scene`,
`scene_boundary_shots`) и на границе сцен (`adjacent_scenes`) показывается
состояние связи. При применённом переносе (Фаза 2) — метка «учитывается перенос
из: Сцена X»; устаревший перенос показывается отдельно и не выдаётся за
действующий.

**Длительность.** Берётся из плана сценария (`shot.duration_sec`); сохранённая
длительность видео-ассета в `studio.db` не персистится, поэтому лента не
выдаёт её за факт.

**Предпросмотр.** Последовательный проигрыватель в браузере (клип → `<video>`,
кадр → изображение, иначе «нет материала») по длительностям планов через
`setTimeout` — без ffmpeg и без сборки файла.

**Фильтр и поиск (Film Reel).** Верхняя карточка фильма умеет сужать показ
**целиком на клиенте** — без нового API и без новых сущностей, потому что данные
всего фильма уже загружены. Контролы: текстовый поиск (по сцене: заголовок,
`scene_id`, локация, персонажи; по плану: описание, тип, `shot_id`), фильтр по
эпизоду и фильтр «Показать только»: «Все», «Есть клип», «Mock», «Устарело»,
«Кадр без клипа», «Требует обновления», «Нет материала», «Без рабочей области»,
«Несоответствие». Фильтр **не меняет** канонический порядок сцен и планов — он
только исключает неподходящие сцены/планы. Совпадение по тексту на уровне сцены
показывает все её планы; совпадение на уровне плана — только совпавшие. Статусы
«Без рабочей области» и «Несоответствие» действуют на уровне сцены (показывают
её целиком). Сводка и последовательность предпросмотра пересчитываются по
отфильтрованному набору; при активном фильтре показывается метка «показано сцен:
X из Y» и кнопка «Сбросить фильтр»; пустой результат даёт «Ничего не найдено по
фильтру».

**API (реализовано).**
| Метод | Путь | Роль | Назначение |
|---|---|---|---|
| GET | `/studio/reel?chapter=&scene_id=&scene_ids=` | reader | Лента области (read-only); без параметров — весь фильм |

**Ответ `data`.** `scope` (`scene|sequence|episode|film`), `chapter`
(`null` для `film`), `scene_ids`, `film{book_id,title,episode_count}`,
`scenes[]` (с `shots[]`, `continuity_from_prev_scene`, `transfer`, `warnings`),
`sequence[]` (`kind`: `clip|frame|placeholder`), `summary{scene_count, shot_count,
clip_count, frame_count, placeholder_count, mock_count, stale_count,
total_duration_sec}`, `limitations[]`. Недостающая сцена в `scene_ids` попадает
в `limitations`, а не придумывается.

**Границы.** Уже утверждённые кадры не меняются. Автоматической генерации и
массовой обработки нет: создание видео — только по явному действию режиссёра,
по умолчанию mock. Монтаж/сборка/MP4 — вне Фазы 3.

**Тесты.** Backend: `runtime/tests/test_studio_reel.py` (28, включая области
`film`). Frontend: `arkaim-web/tests/unit/studio-story-reel.test.tsx` (6) и
`arkaim-web/tests/unit/studio-film-reel.test.tsx` (13: базовый показ и
фильтр/поиск).

## 11. План сборки последовательности (Фаза 4) — тайминг · разрывы · исполнители

**Что это.** Режиссёрский **план сборки** последовательности фильма: непрерывный
накопительный тайминг отрезков, выявление **разрывов** (где нет готового клипа),
переходы на стыках, сводка по исполнителям (с флагом «смешанные исполнители») и
**текстовый план** (раскадровка) для последующего переноса в монтажную программу.

**НЕ** монтаж, НЕ финальный cut, НЕ рендер, НЕ MP4, НЕ ffmpeg. Это **подготовка**
к финальному монтажу вне системы (например, DaVinci Resolve). Модуль ничего не
создаёт, не генерирует и не удаляет — только вычисляет и группирует.

**Базовый принцип.** Все данные берутся из уже построенной **Story Reel**-ленты
(`studio.reel` / `GET /studio/reel`). Порядок отрезков **строго канонический**
(геном → сцены, сценарий → планы) — не переупорядочивается.

**Правило готовности:** отрезок считается «готовым к сборке» только если клип
есть и его статус `ready` (**реальный** клип). `mock`, `stale`, `frame`,
`placeholder` не считаются готовыми — они образуют **разрывы**. Разрывы
группируются в **непрерывные** цепочки подряд идущих не-готовых отрезков с
общим таймингом.

**Где живёт код.**
- Логика (чистая): `core/CORE/studio/sequence.py` — функции `build_plan`,
  `segment_kind`, `executor_label`, `executor_key`, `fmt_timecode`,
  `render_plan_text`.
- Роут: `runtime/core/routes/studio.py` — `GET /studio/sequence` (общий с
  `/reel` сбор данных через `_collect_reel`).
- UI: `arkaim-web/src/app/studio/sequence.tsx` (карточка «Последовательность
  фильма (план сборки)» в `page.tsx`) + типы в `arkaim-web/src/app/studio/types.ts`.

**Область.** Как у `/studio/reel`: `scene_id`, `scene_ids`, `chapter`; без
параметров — **весь фильм**. Порядок **канонический**.

**Что возвращается (план).**
- `segments[]`: каждый отрезок с `start_sec`, `end_sec`, `kind`, `ready`,
  `clip_status/frame_status`, `executor{...}`, `executor_key/label`,
  `scene_id/chapter/shot_id`, `transition_to_next`, `scene_boundary_after`.
- `assembled[]`: только готовые (`ready`) отрезки — **список для сборки в DaVinci**.
- `gaps[]`: максимальные непрерывные группы не-готовых — с `start_sec/end_sec`,
  `kinds`, `shot_ids`, `segment_count`.
- `transitions[]`: переходы между соседними отрезками (включая разрывы).
- `executors[]`: сводка по готовым отрезкам (`key/label, count, duration_sec, shot_ids`).
- `executor_mixed` (bool), `summary{...}` (включая `ready_count`, `assembled_count`,
  `gap_count`, `assembled_duration_sec`, `gap_duration_sec`, `executor_count`),
- `limitations[]`, `plan_text` (человекочитаемая раскадровка), `scope`, `chapter`,
  `scene_ids`, `film`.

**Важные детали.**
- Последний отрезок всего фильма **не** имеет флаг границы сцен.
- `executor_key` — стабильный ключ для группировки; `executor_label` — краткая
  человекочитаемая метка (`provider · model` и др.).
- Mock-клип не попадает в `assembled` (он не «готовый» реальный клип) — он
  показывается в сегментах и учитывается в `mock_count`, попадая в `gap`.
- Строка `plan_text` экспортируется двумя кнопками: «Копировать план» (clipboard)
  и «Экспорт плана (TXT)» (скачивание файла `film-sequence-YYYYMMDD-HHMMSS.txt`).
  Также есть переключатель «Показать/Скрыть текстовый план» для inline-просмотра.
- Кнопка **«Экспорт EDL (XML)»** генерирует упрощённый EDL-файл
  (`film-sequence-YYYYMMDD-HHMMSS.xml`) с таймингами готовых отрезков
  (только `ready` клипы). Формат — XML с `<clip>` записями: `shot_id`, `scene_id`,
  `source` (clip asset), `start_sec`, `end_sec`, `duration_sec`, `executor`,
  `transition`. Разрывы и не-готовые отрезки не попадают в EDL. Это не монтаж,
  а справочный файл для переноса в DaVinci Resolve вручную.
- UI отображает сводку, списки исполнителей (с пометкой «смешанные»), таблицу
  отрезков и блок «Разрывы» при их наличии. Сворачиваемые разрывы: клик раскрывает
  детали (shot_ids, kinds, тайминг). Фильтр «Только готовые» сужает таблицу
  до отрезков со статусом `ready`.

**API.**
| Метод | Путь | Роль | Назначение |
|---|---|---|---|
| GET | `/studio/sequence?chapter=&scene_id=&scene_ids=` | reader | План сборки (read-only); без параметров — весь фильм |

**Тесты.** Backend: `runtime/tests/test_studio_sequence.py` (26). Frontend:
`arkaim-web/tests/unit/studio-sequence.test.tsx` (6).
