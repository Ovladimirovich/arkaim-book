# PILOT FILM PLAN — план первого законченного озвученного фильма

**Тип:** план пилота (документ 4 из комплекта)
**Дата:** 2026-10-14
**Статус:** DRAFT — зависит от OWNER-GO (O1, O2, O3, O4) и результатов Этапа 0
**Главный документ:** `docs/MEDIA_PRODUCTION_MASTERPLAN.md`
**Спецификации:** `docs/ARKAIM_STUDIO_SPEC.md`, `docs/MEDIA_EXECUTORS_SPEC.md`

---

## Простыми словами

1. **Что было целью?** — Описать путь от знаний книги до готового озвученного MP4 (60–90 с) как первый законченный результат, который владелец может посмотреть и принять.
2. **Что реально сделано?** — План написан; реальный замер железа (Этап 0) ещё не сделан, поэтому точные цифры (скорость, VRAM, длительность клипа) не обещаются.
3. **Что получилось?** — DRAFT (ожидает OWNER-GO и Этапа 0).
4. **Есть ли проблемы?** — Да: (а) без OWNER-GO на AudioPlan/контракт (O2/O3) озвучка юридически невозможна; (б) без выбора фрагмента книги (O4) сценарий не написать; (в) без замера (Этап 0) нельзя обещать качество/скорость.
5. **Что предлагается дальше?** — Утвердить O1–O4 → выполнить Этап 0 (замер одной сцены) → по его результатам — Этапы 1–4 до первого MP4.

---

## 1. Цель пилота

**Целевой результат:** MP4 60–90 с, 6–10 шотов, русская озвучка, звуковая атмосфера, титры/субтитры, разрешение 480p, принятый владельцем (**ACCEPTED**).

**Зачем:** доказать, что цепочка «книга → Pulse → MediaPlan/AudioPlan → локальный ComfyUI → TTS → assemble → MP4» работает end-to-end; получить реальные факты (VRAM/скорость/качество) для планирования Этапов 5–8.

**Что НЕ входит:** длинный фильм (>90 с), сложные диалоги, lip-sync, облачные исполнители (если локальный замер не покажет иного), коммерческая эксплуатация.

---

## 2. Этап 0 — ранняя проверка (до всего остального)

**Цель:** одна репрезентативная видео-сцена + образец озвучки на целевом железе. Фиксируем факты, не обещания.

### 2.1 Что проверяем

| Что | Как | Критерий «хорошо» |
|---|---|---|
| ComfyUI запускается, модели загружены | `GET /system_stats` | Нет ошибок |
| Wan2.1 T2V 1.3B генерирует клип 480p | Стандартный workflow `text_to_video_wan`, один промпт | Клип ~5 с, без артефактов |
| VRAM peak ≤ 8 ГБ | Мониторинг GPU (nvidia-smi) | Не OOM |
| Время генерации клипа | Замер от submit до готовности | ≤ 620 с (таймаут MediaClient) |
| Silero TTS озвучивает русский текст | v5_ru, 1 спикер, 48 кГц | WAV чистый, текст разборчив |
| ffmpeg доступен | `ffmpeg -version` | Есть |

### 2.2 Промпт для проверки (репрезентативный)

Взять один шот из `core/KNOWLEDGE/SCENE_PROMPTS.json` (12+ ключевых сцен) — например, сцену с архитектурой/пейзажем Аркаима. Пример (уточнить по файлу):

> «Древний город Аркаим на рассвете, панорамный обзор, золотой свет, дымка, cinematic, 480p»

### 2.3 Что фиксируем (протокол замера)

| Параметр | Факт | Источник |
|---|---|---|
| Модель | wan2.1_t2v_1.3b_fp16 | ComfyUI log |
| Workflow | text_to_video_wan (версия) | ComfyUI |
| Разрешение | 832×480 (ориентир) | Workflow |
| Длительность клипа | ___ кадров @ ___ fps | ComfyUI |
| VRAM peak | ___ GB | nvidia-smi |
| Время генерации | ___ s | Замер |
| Качество (субъективно) | 1–5 | Владелец |
| Silero: голос, длительность WAV | ___ | Замер |

**Протокол прикладывается к этому документу (обновляется после Этапа 0).**

### 2.4 Решение по результатам

| Результат | Действие |
|---|---|
| VRAM ≤ 8 ГБ, время ≤ 620 с, качество 3–5 | Идём дальше (Этап 1) |
| VRAM > 8 ГБ или OOM | Включаем offload CPU; если не помогает → LTX-Video или облачная опция (по O5) |
| Время > 620 с | Вводим async (расширение контракта, OWNER-GO) или укорачиваем клип |
| Качество 1–2 | Другая модель/промпт; если не помогает → облачная опция (по O5) |
| Silero не устраивает | Piper (MIT) или облачный TTS (по O5) |

## 3. Выбор материала (решение O4 — OWNER)

**Кандидаты (из уже размеченного материала):**

| Источник | Что есть | Пример |
|---|---|---|
| `core/KNOWLEDGE/SCENE_PROMPTS.json` | 12+ ключевых сцен с готовыми промптами | Архитектура, ритуалы, пейзажи |
| `core/KNOWLEDGE/screenplay_extracts.json` | Извлечённые сцены/диалоги | Готовые реплики |
| `core/KNOWLEDGE/EPOCH_PALETTES.json` | Палитры эпох | Свет, цвет |
| `core/KNOWLEDGE/CHARACTER_VISUALS.json` | Внешность персонажей | Для референсов |
| `core/KNOWLEDGE/LOCATION_VISUALS.json` | Локации | Для референсов |

**Критерии выбора фрагмента для пилота:**

1. **Один персонаж** (или без персонажей — пейзаж/архитектура) — проще для постоянства.
2. **1 локация** — меньше разрывов.
3. **Короткий диалог** (1–2 реплики) — для проверки озвучки.
4. **Визуально богато** — свет, атмосфера (чтобы показать «вау»-эффект).

**Вопрос владельцу (O4):** какой фрагмент экранизируем? (Предложить 2–3 варианта на основе SCENE_PROMPTS.json.)

## 4. Путь до MP4 (Etапы 1–4)

### 4.1 Этап 1 — Утверждение направления и контрактов

**Действия:**
1. OWNER-GO на главный план (O1).
2. Новый `ADR_AUDIO_PLAN_V0` (O2) — снимает D2-запрет на AudioPlan.
3. Эволюция MEDIA_CONTRACT v1.0 → v1.1 (O3) — audio + assemble + видео-провайдер.
4. Постройка 11 висящих вызовов фронта (перевод на новые маршруты или скрытие).

**Критерий:** ADR принят, контракт v1.1 согласован, pytest/vitest зелёный, нет вызовов несуществующих API.

### 4.2 Этап 2 — Производство клипов

**Действия:**
1. Видео-провайдер Wan в arkaim-media (`ComfyUIProvider(video)`).
2. Подключить `MEDIA_BACKEND_URL` (мост выключен по умолчанию).
3. Минимальный механизм заданий (статусы `pending/generating/completed/failed`).
4. Сохранение клипов в AssetStorage (media_id + lineage).

**Критерий:** из API/UI «сгенерировать шот» → MP4 в `data/visual_assets/`, статус `completed`.

**Зависимости:** Этап 0 (модель работает), Этап 1 (контракт).

### 4.3 Этап 3 — Озвучка

**Действия:**
1. AudioPlan v0 (по новому ADR): реплики, голос, тайминг, атмосфера.
2. TTS-провайдер Silero в arkaim-media (`v5_ru`, 1 голос, 48 кГц).
3. Привязка WAV к сценам FilmProject.

**Критерий:** по каждой сцене пилота есть WAV + тайминг; ошибки видны.

**Зависимости:** Этап 1 (ADR + контракт).

### 4.4 Этап 4 — Сборка, QC, экспорт

**Действия:**
1. `POST /v1/assemble` в arkaim-media (логика ShotAssembler: concat + Ken Burns).
2. Аудиомикс: диктор + атмосфера (+ музыка, если есть).
3. Титры/субтитры (из сценария/AudioPlan).
4. Экспорт MP4 + WAV + SRT.
5. Чек-лист QC (§5).

**Критерий:** MP4 60–90 с проходит QC и принят владельцем (**ACCEPTED**).

**Зависимости:** Этапы 2, 3.

## 5. Чек-лист QC

### 5.1 Технические проверки

| Проверка | Критерий | Инструмент |
|---|---|---|
| Разрешение | 480p (например, 832×480) | ffprobe |
| fps | 16 (стандарт Wan2.1) или agreed | ffprobe |
| Длительность | 60–90 с | ffprobe |
| Аудиодорожки | WAV, 48 кГц | ffprobe |
| Субтитры | SRT синхронизирован | Просмотр |
| Размер файла | Разумный (< 500 МБ) | filesystem |

### 5.2 Качество (субъективное, владелец)

| Проверка | Критерий |
|---|---|
| Визуал | Нет заметных артефактов; стиль/палитра соответствуют эпохе |
| Персонажи (если есть) | Внешность узнаваема между шотами (ContinuityEngine) |
| Камера | Движения плавные, без «плясок» |
| Озвучка | Текст разборчивый, ритм естественный, нет обрывов |
| Атмосфера | Фон не перекрывает диктора; громкости сбалансированы |
| Титры/субтитры | Читаемы, синхронизированы |
| Целостность | Фильм «складывается», нет ощущения набора клипов |

### 5.3 Соответствие книге (provenance)

| Проверка | Критерий |
|---|---|
| Источники | Каждая сцена/реплика ссылается на главу/сцену книги |
| Канон | Локации/персонажи соответствуют VISUAL_KNOWLEDGE |
| Смысл | Текст не искажает замысел автора (IdentityLayer.validate) |

## 6. Ограничения и допущения

| Ограничение | Почему | Что потом (Этапы 5–8) |
|---|---|---|
| 60–90 с, 6–10 шотов | Быстрый end-to-end результат | Длинные эпизоды (Этап 8) |
| 480p | Ограничение VRAM 8 ГБ | 720p/1080p при большей GPU или облачно |
| 1 голос диктора | Простота пилота | Несколько голосов, диалоги (Этап 7) |
| Без lip-sync | Тяжёлые модели | Опционально (Этап 7) |
| Локальный ComfyUI | Решение владельца (основа) | Облачные опции (Этап 8, O5) |
| Без музыки (или простая) | Пилот | MusicGen/фонотека (Этап 7) |

## 8. Риски и ответы

| Риск | Вероятность | Ответ |
|---|---|---|
| Wan 1.3B не помещается в 8 ГБ / медленно | Средняя | Offload CPU → LTX-Video → облачная опция (O5) |
| Silero CC BY-NC не подходит (коммерция) | Низкая (пилот) | `v5_cis_base` (MIT) или облачный TTS (O5) |
| Качество 1–2 | Средняя | Другой промпт/модель; если нет — облачная опция (O5) |
| Время клипа > 620 с | Средняя | Async (расширение контракта, OWNER-GO) или короче клип |
| Разрывы между шотами | Средняя | ContinuityEngine + референсы (Этап 6) |
| Владелец не утвердит материал (O4) | Низкая | Предложить 2–3 варианта из SCENE_PROMPTS |

---

## 9. Критерии приёмки пилота

1. **MP4 готов** (60–90 с, 480p, озвучка, атмосфера, титры/субтитры).
2. **QC пройден** (§5): технические + субъективные + provenance.
3. **Владелец принял** (status: **ACCEPTED**).
4. **Протокол Этапа 0 заполнен** (реальные VRAM/скорость/качество).
5. **Нет нарушений границы** (arkaim не вызывает ComfyUI напрямую; assemble на media-стороне).
6. **Воспроизводимо** (lineage полный: книга → сценарий → планы → клипы → MP4).
