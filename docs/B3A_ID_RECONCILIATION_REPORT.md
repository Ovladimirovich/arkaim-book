# B3a — Согласование идентификаторов World Engine и WorldModel

Статус: **DOCUMENTED**. Исследование завершено; изменений runtime, Temporal, API и UI не вносилось.

## Простыми словами

**Что было целью?** Проверить, можно ли достоверно связать карточки World Engine (`region_*`) с эпохами и объектами Времени мира (`arkaim`, `аркаим`, `event_*`).

**Что реально сделано?**
- Проверены два реальных источника данных проекта.
- Проверены 524 сущности World Engine и 36 канонических идентификаторов WorldModel.
- Проверены обычные поля и все вложенные поля сущностей.
- Код и интерфейс не менялись.

**Что получилось?** **PASS для B3a как исследовательской задачи.** Подтверждённого автоматического ключа между двумя пространствами идентификаторов в данных нет.

**Есть ли проблемы?** Да, средняя: `region_arkaim` и `arkaim` похожи по смыслу, но совпадение названия не является подтверждением связи. Автоматически соединять их нельзя.

**Что предлагается дальше?** Создать отдельно курируемый файл соответствий, где каждое соответствие подтверждено источником проекта. Только после этого возвращаться к B3b.

## Источники

1. **World Engine entities** — `core/CORE/WORLD_MODEL/*.json`.
   - 524 сущности в 12 категориях.
   - Примеры идентификаторов: `region_arkaim`, `region_gardarika`.
   - Поля: `id`, `name`, `name_ru`, `category`, `description`, `properties`, `source`, `confidence`, `provenance_category`, `provenance_notes`, `source_level`, у части сущностей `relationships`.

2. **Canonical WorldModel / Temporal** — `core/CORE/narrative_engine/data/WORLD_MODEL.json`.
   - 36 идентификаторов в исследованных коллекциях: эпохи, локации, технологии, цивилизации, canonical events.
   - Примеры идентификаторов: `arkaim_era`, `arkaim`, `аркаим`, `гиперборея`, `hyperborea`, `event_arkaim_construction`.
   - Этот источчик используется `WorldModel.get_temporal_node()` и `get_temporal_chain()`.

Архитектурное подтверждение разделения источников находится в `core/CORE/narrative_engine/world_engine.py`, строки 85–88: `WorldModelExt` загружает категории из `WORLD_MODEL/*.json`, а `WorldModel` отдельно загружает эпохи и события из `WORLD_MODEL.json`.

## Сущности, для которых соответствие пока невозможно установить

Нельзя достоверно установить соответствие для всех 524 сущностей World Engine, пока в данных нет явного поля или отдельного авторитетного crosswalk-файла.

В частности, нельзя автоматически утверждать:

- `region_arkaim` = `arkaim`;
- `region_arkaim` = `аркаим`;
- `region_gardarika` = `гиперборея`;
- любое другое соответствие по похожему названию.

Это не означает, что сущности разные. Это означает только: **проект пока не содержит доказуемой связи между этими ID**.

## Почему не выполнено заполнение `entity_ids`

В `core/CORE/narrative_engine/world_model.py:380` поле `entity_ids` временного узла сейчас задаётся пустым списком. Его можно заполнить только после появления авторитетного crosswalk. Иначе frontend получит ложные связи и будет показывать неверные утверждения о мире.

## Решение, принятое для следующего шага

Не менять UI B3, не менять Temporal и не заполнять связи по эвристике.

Следующая отдельная задача должна создать курируемый источник соответствий, например:

```json
{
  "region_arkaim": {
    "world_model_ids": ["arkaim"],
    "evidence": "указать главу, фрагмент или другой источник подтверждения"
  }
}
```

Формат является предложением для B3a-результата, а не новой архитектурой. Каждое соответствие должно иметь подтверждение. Без `evidence` запись не должна считаться авторитетной.
