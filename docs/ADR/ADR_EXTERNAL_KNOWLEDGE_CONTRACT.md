# ADR — Единый источник истины для внешних знаний (редакторский контракт)

**Тип:** Architecture Decision Record
**Дата:** 2026-10-27
**Статус:** ✅ ACCEPTED (Этап 2 плана «Единый последовательный план устранения проблем Arkaim»)
**Контекст принятия:** Этап 2 плана — закрепление документированного контракта БЕЗ миграции данных. Закрывает B4 (контракт) и B16 (факт-чек гейт должен поймать ошибку атрибуции «Элиаде/Генон» как пример отсутствия механизма).

## Простыми словами

1. **Что было целью?** — Зафиксировать письменным правилом (контрактом), кто является «хозяином» внешнего знания (археология, академические подтверждения, эзотерические традиции), как помечать «связь с книгой» и почему интерпретация системы никогда не бывает «каноном книги». Плюс — добавить **гейт на вход**: система должна отклонять новую запись, если та претендует на «канон книги», но не лежит в первичном каноническом файле (это ловит дефекты типа «Элиаде», где текст источника ссылается на Генона).

2. **Что реально сделано?** — Написан контракт (этот ADR) и код-проверка (`external_gate.py`), который проверяет ВСЕ новые внешние записи: у каждой должно быть поле `source` (или честный `UNKNOWN`, но не пусто), поле `origin_layer` из трёх допустимых значений, и если это «связь с книгой» — обязательный статус проверки (`book_link_status`). Если запись пытается назваться «каноном», но файл не первичный канонический — проверка её **отклоняет**.

3. **Что получилось?** — **ACCEPTED** (контракт принят) + **IMPLEMENTED** (гейт на вход работает) + **TESTED** (проверки покрыты тестами).

4. **Есть ли проблемы?** — Несерьёзные. Контракт действует для НОВЫХ записей; существующие данные не переклассифицируются на этом этапе (это Этап 3 плана, поштучно). Пустые `source` у старых записей гейт не трогает — это осознанно.

5. **Что предлагается дальше?** — Этап 3 плана (декомпозиция «10 традиций»), который реально трогает данные, опираясь на этот контракт. Ничего не начинаю без отдельного решения.

## Контракт

### Правило 1. «Сырьё» внешних источников — единый источник истины

Факты о традиции/археологии/академике живут ТОЛЬКО в `core/KNOWLEDGE/*`
(`ESOTERIC_CONNECTIONS.json`, `ARCHAEOLOGY.json`, `ACADEMIC_CONFIRMATIONS.json`,
`CROSS_REFERENCES.json` и т.д.). Любая производная проекция в другом слое (например,
`WORLD_MODEL/*`) обязана ссылаться на этот источник через `source: <id in KNOWLEDGE>`
или `DERIVED_FROM`, а не копировать содержимое в независимое «зеркало».

### Правило 2. «Связь с книгой» — отдельное поле со своим статусом обоснованности

Поле `book_connection` не «склеивается» с фактом. Каждая связь с книгой несёт свой
статус обоснованности:
- `book_link_status: VERIFIED` — связь проверена/подтверждена;
- `book_link_status: UNVERIFIED` — связь требует проверки;
- `book_link_status: REJECTS` — связь отклонена (важно сохранять и отклонения).

### Правило 3. «Системная интерпретация» никогда не CANON

Интерпретация системы маркируется `provenance_category=SYSTEM_INTERPRETATION`
(или `DERIVED`) и обязанна содержать явную ссылку на сырьё (`source`).
Запись, претендующая на `AUTHOR_CANON`, допустима ТОЛЬКО внутри первичного
канонического файла (`is_canon_file()`), т.е. `BOOK_DOCUMENT` / `SYNOPSIS_DOCUMENT`
/ `AUTHOR_INTENT`.

### Правило 4. Контракт вступает в силу для НОВЫХ записей

Существующие записи не переклассифицируются «массово» и не приводятся к контракту
принудительно на этом этапе — они приводятся к нему поштучно в Этапе 3 плана.

## Гейт на вход (validator)

Новая внешняя запись, прежде чем быть принятой, проверяется
`validate_external_record()` в `external_gate.py`. Обязательные поля:

| Поле | Требование | Допустимые значения |
|---|---|---|
| `source` | не null, не пустое | реальная ссылка (`<file>#<id>`) или `UNKNOWN` |
| `origin_layer` | обязательно | `EXTERNAL_FACT` / `BOOK_LINK` / `SYSTEM_INTERPRETATION` |
| `book_link_status` | обязательно при `origin_layer=BOOK_LINK` | `VERIFIED` / `UNVERIFIED` / `REJECTS` |
| `provenance_category` | если `AUTHOR_CANON` → должен быть канонический файл | иначе запись отклоняется (факт-чек гейт, тип B16) |

## Последствия

- **Для Этапа 3:** теперь есть правило, по которому зеркала вообще существуют —
  они производные проекции с ссылкой `DERIVED_FROM`, а не независимые копии.
- **Для Этапа 5 (гипотезы):** любая предлагаемая система фактом попадает в систему
  только с честной маркировкой `SYSTEM_INTERPRETATION` и `source`, никогда как CANON.
- **Для Этапа 8 (библиография):** контракт уже требует поле `source` — это и есть
  причина, почему B8 не блокирует этапы 1–6, а только 8: механика готова, осталось
  заполнить реальные ссылки владельцем.
- **Риск регрессии:** минимальный — гейт проверяет только НОВЫЕ записи; существующие
  пайплайны и данные не изменяются.
