## Простыми словами

1. **Что было целью?** — Спроектировать весь путь от знаний книги «Наследие Аркаим» до готового озвученного видео (сценарий → кадры → клипы → голос → звук → монтаж → MP4) и зафиксировать, как это будет устроено, в каком порядке делать и что решить владельцу.
2. **Что реально сделано?** — Исследовано фактическое состояние кода (Pulse, визуальные знания, Studio, Film Studio, MediaPlan, arkaim-media, фронтенд), проверены действующие ADR и контракты, изучены внешние исполнители (официальные документы ComfyUI, Runway, RunComfy, Silero TTS — данные на 2026-10-14), написан комплект из четырёх согласованных документов.
3. **Что получилось?** — PARTIAL (план готов, реализация не начиналась по условию задачи).
4. **Есть ли проблемы?** — Да, три существенные: (а) фронтенд зовёт 11 удалённых API-адресов — кнопки генерации/сборки сейчас падают; (б) сборка видео (`ShotAssembler`) написана, но намеренно отвязана от API границей ADR; (в) аудиоконтур юридически заблокирован решением D2 — для него нужно официальное новое решение владельца, а не скрытая реализация. Ничего из этого не блокирует план, но требует решения в Этапе 1.
5. **Что предлагается дальше?** — Утвердить этот генеральный план (OWNER-GO по Приложению A), затем выполнить Этап 0 (технический замер одной видеосцены на целевом оборудовании) и только после его результатов — Этапы 1–4 до первого MP4.

### 2.2 Роли (не нарушать)

| Слой | Отвечает | Не отвечает |
|---|---|---|
| Pulse | Что известно из книги, provenance, канон | Генерацию, монтаж |
| Arkaim (описания) | SceneContext, MediaPlan, VideoScenario, AudioPlan, проект фильма | Execution (модель, seed, workflow) |
| Arkaim Studio | Управление производством, утверждения, пересборка | Понимание книги, графы узлов |
| arkaim-media | Исполнение заданий, выбор backend/workflow, файлы | Смысловые поля книги |
| ComfyUI (и иные) | Конкретная генерация медиа | Контракты, статусы фильма |

### 2.3 Исполнители — гибкая система (основа локальная; опции подключаемы)

**Основной принцип:** не привязывать архитектуру к одной модели, одному workflow, одному GPU или одному облачному сервису. Arkaim Studio управляет производством, Pulse отвечает за содержание, генерацию выполняют подключаемые исполнители; конкретный генератор **не зашивается** в логику фильма.

**Основа планирования** (решение владельца, 2026-10-14): локальный ComfyUI на NVIDIA GPU с 8 ГБ VRAM, модель Wan 2.1 T2V-1.3B, клипы 480p — **как проверяемая конфигурация, а не догма**. Совместимость не считается доказанной по заявленным минимальным требованиям: для каждого рабочего варианта фиксируются фактические VRAM, разрешение, длительность и скорость.

**Фактический профиль оборудования (отдельно от целевого NVIDIA 8 ГБ; замер 2026-10-14):**

| Параметр | Факт сегодня | Цель плана |
|---|---|---|
| GPU | AMD Radeon RX 570, 4 ГБ | NVIDIA GPU, 8 ГБ VRAM |
| PyTorch | 2.12.1 **+cpu** (CUDA нет) | GPU-режим |
| ComfyUI | 0.34.5, запуск с `--cpu`, порт 8188 | тот же ComfyUI, GPU |
| Локальная генерация видео (Wan 2.1) | **не выполняется** (нет NVIDIA, 4 ГБ < 8 ГБ) | Этап 0 на целевом железе |
| Облачная генерация изображений (Agnes) | **работает** — submit локальный (CPU-режим достаточен) → генерация в Agnes cloud | остаётся как есть |

Следствие: **на фактическом железе доступен только гибридный путь** (локальный ComfyUI как submit-машина + облачные исполнители). Локальное видео-производство (Wan 2.1 T2V, Этап 0) **зависит от получения целевого NVIDIA 8 ГБ** — до тех пор видео-этапы плана не запускаются. Первый подключённый по процессу §3.1 спецификации исполнитель — **Agnes (image, free)**: проверен сквозным запуском 2026-10-14, запись реестра `available` (`docs/MEDIA_EXECUTORS_SPEC.md` §3).

**Цепочка резервных способов исполнения** (порядок, не догма):

1. Основной локальный ComfyUI workflow (Wan2.1 T2V 1.3B).
2. Другой совместимый локальный workflow/нода (например, LTX-Video; по мере обнаружения — Agnes и иные).
3. Настроенный удалённый ComfyUI / облачный workflow / API внешнего исполнителя (RunComfy, Comfy Router, Runway — только при разрешённой политике расходов O5).
4. Если подходящего варианта нет — понятное состояние **«исполнитель недоступен»**, без фиктивного результата.

Переключение выполняется **только между исполнителями, реально поддерживающими требуемую операцию** (image/video/audio); изменение качества, скорости, ограничений и стоимости показывается пользователю; платные вызовы не выполняются без заранее разрешённой политики расходов.

**Подключение возможностей по мере обнаружения:** новые исполнители/workflow добавляются постепенно (пользователь предлагает → инженер изучает фактические входы/выходы/зависимости → проверяет → подключает к реестру). Первый отработанный пример — нода **Agnes** (генерация изображений, `image`, free): фиктивный адаптер не создавался — шаблон снят с фактического графа, параметры сопоставлены явно, подключение проверено одним сквозным запуском 2026-10-14 (запись реестра `available`). Подробная спецификация реестра, контрактов и фолбэка — `docs/MEDIA_EXECUTORS_SPEC.md`.

### 2.4 Контракты, требующие эволюции (связаны с решениями OWNER)

1. **AudioPlan** — новый доменный контракт в Arkaim (по образцу MediaPlan: intent + provenance + lineage, без execution-полей). Требует нового ADR (пересмотр D2 — решение O2).
2. **MEDIA_CONTRACT v1.0 → v1.1** — расширение execution-envelope: `media_kind=audio`, видео-провайдер Wan, `POST /v1/assemble`. Требует owner-GO (MEDIA_CONTRACT §7.5 — решение O3).
3. **Статусы заданий** — отслеживание длинной генерации (сейчас синхронный `/v1/generate`, таймаут 620 с): если реальное время клипа превышает таймаут — нужен async (также контракт, решение откладывается до результатов Этапа 0).

## 3. Полный производственный процесс (целевой)

| # | Шаг | Исполняет | Уже есть | Что доработать |
|---|---|---|---|---|
| 1 | Выбор материала книги | Pulse | Слои, RAG, SCENE_PROMPTS, screenplay_extracts | Мост «запрос владельца → пакет материалов для сцены» (Studio) |
| 2 | Сценарий фильма | Arkaim (LLM как голос, не как источник) | VideoScenarioBuilder, narrative_engine/story | Редактирование и утверждение владельцем в Studio |
| 3 | Режиссёрский план и раскадровка | Arkaim | FilmProjectStore (сцены/шоты), VideoContext, CAMERA/SHOT_LIBRARY | Привязка шотов к MediaPlan + референсам |
| 4 | Визуальные ориентиры | Arkaim | CHARACTER_VISUALS, LOCATION_VISUALS, ContinuityEngine, ReferenceAsset (Studio) | Сохранение утверждённых кадров как источников для I2V/регенерации |
| 5 | Генерация клипов | arkaim-media → локальный ComfyUI (Wan2.1 T2V 1.3B) | MediaClient, `/v1/generate`, image-провайдер ComfyUI | **Видео-провайдер Wan** (Этап 2), отслеживание статуса |
| 6 | Озвучка и звук | arkaim-media → Silero TTS + фонотека/генераторы | `sound_design` в VideoScenario, AudioPlan-точка в enum | **AudioPlan + TTS-провайдер** (Этап 3, решения O2/O3) |
| 7 | Монтаж | arkaim-media (assemble) → FFmpeg | ShotAssembler (код), ffmpeg-логика Ken Burns/concat | **assemble по контракту**, аудиомикс, титры/субтитры (Этап 4) |
| 8 | Проверка | Владелец + автоматические проверки | approve/reject в Studio, CanonValidator | Чек-лист QC (документ 4), статус «ожидает проверки» |

## 4. Генеральная дорожная карта

Порядок строго последовательный между этапами; внутри этапа допустим параллелизм. Приоритет — ранний целостный результат: **первый MP4 закрывается на Этапе 4.**

### Этап 0 — Технический замер (спайк, без правок кода Arkaim)

- **Цель:** получить реальные факты о локальной видеогенерации и TTS до планирования сроков.
- **Содержание:** установить/проверить ComfyUI + модели Wan2.1 (T2V-1.3B, umt5, VAE); прогнать одну репрезентативную сцену (стандартный workflow `text_to_video_wan`); прогнать образец русского текста через Silero TTS; проверить наличие ffmpeg.
- **Измеряем:** пиковое потребление VRAM, время генерации клипа 480p, субъективное качество, стабильность, размеры файлов моделей.
- **Зависимости:** оборудование (NVIDIA 8 ГБ VRAM).
- **Критерий готовности:** заполнена таблица фактов «модель / параметры / VRAM / время / качество»; вывод «модель подходит → дальше» либо «нужна альтернатива → корректировка плана».
- **Проверка:** протокол замера (скриншоты/логи ComfyUI) прикладывается к `docs/PILOT_FILM_PLAN.md`.
- **Риски:** модель не помещается/медленно — варианты ответа описаны в документе 4 (§5), решение о смене модели принимается по факту замера.

### Этап 1 — Утверждение направления и контрактов

- **Цель:** снять архитектурные запреты и привести интерфейс в согласованное состояние.
- **Содержание:** OWNER-GO по Приложению A; новый `ADR_AUDIO_PLAN_V0` (замена/уточнение D2); эволюция MEDIA_CONTRACT до v1.1 (audio + assemble + видео-провайдер); починка 11 висящих вызовов фронта (перевод на существующие маршруты или скрытие до их появления).
- **Переиспользуется:** все текущие ADR и контракты (расширяются, не заменяются).
- **Критерий готовности:** ADR принят и лежит в `docs/ADR/`; контракт v1.1 согласован в arkaim-media; прогон `runtime/tests` зелёный; на страницах фронтенда нет вызовов несуществующих адресов.
- **Проверка:** pytest (backend), vitest/eslint (frontend), ручной проход страниц `visual`, `assets`, `film-studio`.
- **Зависимости:** Этап 0 (чтобы понимать, нужен ли async).

### Этап 2 — Производственный контур видео

- **Цель:** шот из проекта фильма превращается в видеоклип локально, без ручных операций.
- **Содержание:** видео-провайдер Wan2.1 в arkaim-media (workflow `text_to_video_wan`, ввод: prompt/негатив/размер/длительность из MediaPlan, вывод: видеофайл → `media_id`); подключение `MEDIA_BACKEND_URL`; механизм статусов задания (G5) — минимальный polling/статус в Studio; сохранение результата в AssetStorage.
- **Переиспользуются:** MediaClient, `/v1/generate`, FilmProjectStore, MediaPlanBuilder, AssetStorage.
- **Критерий готовности:** из UI/API — «сгенерировать шот» → файл клипа в `data/visual_assets/`, статус шота `completed`, при ошибке — `failed` с текстом.
- **Проверка:** интеграционный тест по цепочке (mock или реальный локальный ComfyUI в dev-окружении); ручной прогон 2–3 шотов.
- **Зависимости:** Этап 0, 1.

### Этап 3 — Аудиоконтур (диктор)

- **Цель:** русский дикторский текст по сценам в виде WAV-дорожек, привязанных к таймлайну.
- **Содержание:** AudioPlan v0 (по новому ADR: реплики, говорящий, настройки голоса, тайминг, атмосфера); TTS-провайдер Silero в arkaim-media (v5_ru, до 5 голосов, 48 kHz); привязка дорожек к сценам FilmProject.
- **Переиспользуются:** `sound_design` из VideoScenarioBuilder, тексты/диалоги книги, enum `media_kind=audio` (уже зарезервирован).
- **Критерий готовности:** по каждой сцене пилота есть WAV + тайминг; ошибки озвучки видны в Studio.
- **Проверка:** прослушивание, сверка текста с утверждённым сценарием, автоматическая проверка длительностей против таймлайна.
- **Зависимости:** Этап 1 (ADR + контракт).

### Этап 4 — Сборка, QC и первый MP4 (закрытие пилота)

- **Цель:** готовый озвученный MP4 по документу 4.
- **Содержание:** assemble по контракту (логика на базе ShotAssembler: concat клипов, Ken Burns для статичных кадров, аудиомикс диктор+атмосфера+музыка, титры/субтитры, экспорт); чек-лист QC; выдача результата.
- **Переиспользуются:** ShotAssembler (код), `data/film_output/`, approve/reject Studio.
- **Критерий готовности:** MP4 60–90 с проходит чек-лист QC документа 4 и принят владельцем (**ACCEPTED** — цель проекта достигнута).
- **Проверка:** просмотр владельцем; технические проверки ffmpeg (разрешение/фпс/дорожки).
- **Зависимости:** Этапы 2, 3.

### Этап 5 — Arkaim Studio как рабочее место

- **Цель:** весь цикл управляется через UI (документ 2), без консольных шагов.
- **Содержание:** страница Studio с тремя представлениями (А/Б/В); статусная модель «планируется → готово к генерации → выполняется → ожидает проверки → утверждено → в монтаже → ошибка»; регенерация отдельных шотов/реплик; монтажная область (порядок, длительности, громкости); пересборка затронутых частей.
- **Переиспользуются:** `/studio/*` (14 роутов), FilmProjectStore, страница `film-studio` (как основа), WebSocket (прогресс).
- **Критерий готовности:** владелец создаёт новый ролик целиком через UI; неудачный шот перегенерируется поштучно без полной переделки.
- **Проверка:** сквозной сценарий браузерного теста + ручной проход владельца.
- **Зависимости:** Этапы 2–4.

### Этап 6 — Постоянство персонажей и качество

- **Цель:** персонажи и стиль узнаваемы между кадрами.
- **Содержание:** утверждённые кадры как референсы (I2V/Fun InP — с учётом ограничений VRAM, см. документ 3); связка ContinuityEngine ↔ референсы Studio; повторное использование принятых версий; сохранение версий workflow в заданиях.
- **Критерий готовности:** 10-шотовый ролик сохраняет внешность персонажа и палитру сцены между соседними шотами (оценка владельца).
- **Зависимости:** Этап 5.

### Этап 7 — Полное аудиопроизводство

- **Цель:** диалоги, несколько голосов, музыка, управляемые эффекты.
- **Содержание:** голоса персонажей (расширение TTS), музыкальная дорожка (локальный генератор или CC0-фонотека — выбор по замеру), автоматическое сведение, опционально синхронизация губ (тяжёлые модели — только по отдельному решению).
- **Критерий готовности:** ролик с диалоговой сценой и музыкой, сведённый автоматически.
- **Зависимости:** Этап 4.

### Этап 8 — Масштабирование и альтернативные исполнители

- **Цель:** подключаемость облачных исполнителей, длинные проекты, контроль расходов.
- **Содержание:** реестр возможностей (документ 3 §3) в Studio; адаптеры RunComfy/Comfy Router/Runway (опционально, платно); возобновление прерванной работы; учёт потраченных кредитов; пересборка только изменённых частей.
- **Критерий готовности:** один и тот же шот выполняется как локально, так и через выбранный облачный backend без изменения смысла задания.
- **Зависимости:** Этапы 5, 1 (контракт).

## Приложение B. Риски и ответы

| Риск | Вероятность/impact | Ответ |
|---|---|---|
| Wan2.1 T2V-1.3B на 8 ГБ VRAM медленно или нестабилен | Средняя / высокий | Этап 0 меряет раньше вложений; варианты — offloading ComfyUI, более короткие клипы, LTX-Video как лёгкая альтернатива, платный API (решение O5) |
| Время клипа > таймаута синхронного `/v1/generate` (620 с) | Средняя / средний | Этап 0 фиксирует время; при превышении — async-расширение контракта (в OWNER-решения) |
| Качество Silero как диктора не устроит владельца | Средняя / средний | Замер на реальном отрывке (Этап 0); альтернатива — облачный TTS (платно, O5) |
| Размывание границы (очередь/сборка/аудио в Arkaim) | Средняя / высокий | Все изменения — через ADR и контракт (O2/O3); тесты границы остаются в силе |
| Фронтенд-регресс из-за починки 11 вызовов | Низкая / средний | Перевод на существующие маршруты + vitest + ручной проход |
| «Бесконечный аудит» вместо продукта | Средняя / высокий | Этап 0 ограничен одним сценарным замером; после него — только Этап 1+ к первому MP4 |
