# Визуальные карточки «Атлантида» и «Океания»: конфликт после канонизации локации

Дата: 2026-10-21 · Режим: только чтение, данные не изменялись.

## 1. Вопрос

После того как «Атлантида» и «Океания» были признаны одним местом (решение владельца 2026-10-20, `core/KNOWLEDGE/location_aliases.json`), в визуальном слое
`core/CORE/visual/VISUAL_KNOWLEDGE/LOCATION_VISUALS.json` остались **две карточки одного места** с разной архитектурой, палитрой и звуком.

Требовалось: установить происхождение обеих карточек, определить их класс по словарю проекта и выяснить, какое существующее знание должно быть источником визуальной формы.
Ничего не объединялось и не переписывалось.

## 3. Класс по словарю проекта

Словарь — `core/CORE/narrative_engine/source_levels.py` (`ProvenanceCategory`): `AUTHOR_CANON`, `DERIVED`, `EXTERNAL_SOURCE`, `RECONSTRUCTION`, `HYPOTHESIS`, `ARTISTIC_MODEL`, `FUTURE_EXTRAPOLATION`, `UNKNOWN`.

| Класс | Подходит ли обеим карточкам | Почему |
|---|---|---|
| `AUTHOR_CANON` | **Нет** | Канон — «прямое утверждение из первоисточника (КНИГА.md)». В книге физического описания южной цивилизации нет: «коралл» 0, «биолюминесцент» 0, «Средиземномор» 0, «оливков» 0, «амфитеатр» 0, «гаван» 0, «подводн» 0, «тропическ» 0, «пальм» 0. «мрамор» встречается 2 раза — и относится к Гиперборее |
| `AUTHOR_MATERIAL` | **Термина в проекте нет** (0 совпадений). Ближайшее — `SourceLevel.AUTHOR_INTERPRETATION` с UI-меткой «Материалы автора» | Это *уровень* доверия для авторской интерпретации, а не категория для выдуманной визуальной формы. Карточки не выведены из авторского материала — они придуманы |
| `DERIVED` | **Нет** | «Выведено из канона логическим анализом»: канон не содержит этих деталей, выводить нечего |
| `RECONSTRUCTION` | **Нет** | «Восстановление на основе внешних данных + канона»: внешнего источника, обосновывающего именно коралловые башни или мраморные гавани, нет |
| `FICTION` | **Термин вне словаря проекта** | Встречается один раз в неотслеживаемом корневом документе `World_Explorer_Architecture_v1.md` с другой мнемоникой (`FICTION_ARTISTIC 0.2`) |
| **`ARTISTIC_MODEL`** | **Да — обе** | «Художественное допущение, визуальная интерпретация» (уровень по умолчанию — `MYTHOLOGICAL`, 0.7). Именно так проект уже классифицирует соседние визуальные артефакты: `EPOCH_PALETTES.json` — «Палитры эпох — художественная модель», `SCENE_PROMPTS.json` — «Промпты сцен — визуальная модель», `ENERGY_OF_PLACES.json` — «Энергия мест — художественная модель» (`is_canon=False`) |

**Вывод по классу: обе карточки — `ARTISTIC_MODEL` (художественная модель), а не канон и не реконструкция. Разница между ними — в том, что одна из них позже получила опору в других артефактах проекта, а вторая — нет.**

## 5. Какое знание должно быть источником визуальной формы

Единственный в проекте источник визуальной формы, привязанный к этой цивилизации, — **«сине-стальная» семья**:
`MAP_DATA` (цвет региона `#1E3A5F`) → `EPOCH_PALETTES` («Океания (упадок)») → `GENOME` (`conflict_атлантида_гиперборея`).

Эта семья совпадает с карточкой **«Атлантида»** (2 общих цвета) и **не совпадает** с карточкой **«Океания»** (0 общих цветов). Канонические подсказки сценария (острова, чистые воды, высокие здания, зелёные парки, величественные сооружения острова) согласуются с карточкой «Атлантида» и **противоречат** карточке «Океания» (коралловые башни, подводные купола, биолюминесцентные водоросли, затопленные туманные лагуны).

**Вывод: источником визуальной формы должна быть карточка «Атлантида» (сине-стальная, остовная), перенесённая под канонический ключ «Океания». Карточка «Океания» (коралловая) — отдельное изобретение без опоры в книге и в любом другом артефакте проекта.**

## 6. Что осталось неизвестным

- Точная формулировка промпта и модель, которыми агент заполнял пять заглушек: план лежит вне git (`.mimocode` не отслеживается), в истории промпта нет.
- Слой `core/CORE/visual/VISUAL_KNOWLEDGE/` вообще не покрыт ни классификационным реестром, ни скриптом provenance — поэтому у всех его файлов (включая `CHARACTER_VISUALS.json`, `ATMOSPHERES.json`) происхождение не зафиксировано. Это отдельный пробел слоя, а не только этих двух карточек.
- «Южный город» из книги (КНИГА.md:1214) — единственное архитектурное упоминание юга; в книге оно не развёрнуто, поэтому точную форму зданий канон не задаёт.

## 7. Варианты (ничего не применено автоматически)

| Вариант | Суть | Цена |
|---|---|---|
| **A. Пере-ключить существующую карточку** | Содержимое карточки «Атлантида» переносится под канонический ключ «Океания»; коралловая карточка удаляется | Минимальная, сохраняет связь с палитрой эпохи и генома; визуально исчезает коралловая версия |
| **B. Оставить обе, пометить вторую** | Карточка «Океания» помечается как неподтверждённая гипотеза и исключается из арт-дирекшна | Ничего не теряется, но визуальный слой продолжает держать два ключа на одно место |
| **C. Пересобрать карточку из канона** | Карточка строится заново из `EPOCH_PALETTES` + `MAP_DATA` + текста сценария; текущие детали обеих карточек отбрасываются | Самое честное, но и самая большая работа; результат будет беднее нынешних карточек, потому что канон почти молчит |

**Рекомендация: вариант A** — он согласуется с уже принятым решением «одно место — один id», сохраняет проверенную палитру и не требует новых выдумок. Вариант C имеет смысл, если владелец готов принять более скупую визуальную форму.

## 8. Побочный технический факт

`core/CORE/knowledge/screenplay_scene_knowledge.py::_location_id()` берёт идентификатор локации **из ключей `LOCATION_VISUALS.json`** (проверка «ключ есть в файле»). Поэтому визуальный слой фактически используется как словарь соответствий «заголовок сцены → место».

После канонизации «Атлантида» осталась в визуальном слое лишней **меткой**: сцены 019 и 021 по-прежнему дают `location_id` «Атлантида» и «Океания», а связь с миром корректно приводится к «океания» через утверждённый алиас (`core/KNOWLEDGE/location_aliases.json`). Связи работают, но при любом варианте из §7 словарь визуального слоя стоит привести к каноническому виду (в варианте A — автоматически, в вариантах B и C — отдельным шагом).
