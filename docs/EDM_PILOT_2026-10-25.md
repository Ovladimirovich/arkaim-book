# EDM Pilot — отчёт эксперимента: extended_world → EDM (25.10.2026)

## Простыми словами

1. **Что было целью?** Проверить, что единая модель описаний (EDM) — это не просто JSON-схема,
   а **рабочая модель мира**: можно ли реальные знания Аркаима безопасно в неё выразить,
   ничего не потеряв, и дальше использовать для живых ответов и медиа-планов.
2. **Что реально сделано?** Без массовой миграции (массовая — по решению владельца NO-GO)
   выбран **ограниченный пилот: 5 реальных карточек** из `extended_world`
   (география, климат, архитектура, цивилизации ×2) — и переведены в EDM
   автоматическим конвертером, а не вручную. По каждой карточке сделан
   **обратный сравнительный отчёт**: каждое поле исходника нашло своё место
   (факт / время / явное исключение) — ничего не потеряно.
   Из готовых EDM-карточек сгенерированы **живой вопрос (dialogue) и живой MediaPlan**.
3. **Что получилось?** **PASS.** 5/5 сущностей прошли валидатор; round-trip без потерь;
   все проверки провенанса/UNKNOWN/реконструкций/отношений/времени зелёные (24 теста).
4. **Есть ли проблемы?** Две пометки, не блокер:
   (а) 2-3 поля карточек (color, icon геокарт) признаны **презентационными, а не знанием**
   — не перенесены, но зафиксированы как исключение, не потеря;
   (б) сгенерированные связи (например, «климат степи действует на Аркаим») — выводы,
   помеченные `derived` («не канон»), как и было задумано.
5. **Что предлагается дальше?** Эксперимент даёт основание переводить остальные
   описательные источники (FORM, VISUAL_KNOWLEDGE, canonical, Knowledge Core, DAILY_LIFE…)
   в EDM по тому же сценарию «миграция → обратное сравнение», а затем наполнять
   мир недостающими знаниями в единую структуру.

## Результаты проверок (кратко)

- **Round-trip:** по каждой карточке `pilot.roundtrip_map.properties` записывает
  судьбу каждого свойства: `claim:<path>` (значение побайтово сверено с исходником),
  `time` (era/epoch → time-блок) или `unmapped:<reason>` (явное исключение, не потеря).
  Отчёт: `core/CORE/ENTITY_MODEL/PILOT_ROUNDTRIP_REPORT.json` — 5 карточек, 0 issues.
- **UNKNOWN:** для локаций weather/season — явные unknown-факты со значением null
  (вместо fail-open «clear»). В MediaPlan проецируется как `"weather": "UNKNOWN"`,
  в dialogue — «не установлено». Ни в одном выводе пилота строк `clear`/`late summer` нет.
- **RECONSTRUCTION ≠ CANON:** `civ_arkaim_civilization` (RECONSTRUCTION) →
  статус `reconstructed`, `medium=true`, в dialogue рендерится только с явной пометкой
  «(реконструкция, художественное допущение)», в MediaPlan — с меткой `(MEDIUM)`.
  Каноническая `civ_hyperborea` → `author_canon`, medium=false. Искажений нет.
- **Relations:** исходные `relationships` карточек (в пилоте пусты) сохранены дословно.
  Добавлены 3 **сгенерированные** связи (climate_of / located_in / associated_with)
  — все `derived`, в note прописано «generated during pilot … не канон».
  Они позволяют реально спросить: «какой климат действует на region_arkaim?» → steppe_climate.
- **Temporal:** era/epoch карточек сохранены в time-блке; у steppe_climate эпохи в
  карточке нет → time-блок пустой (не выдуман).
- **Projections:** из одной EDM-карточки получаются и dialogue-фраза, и фрагмент
  MediaPlan (structured_prompt + unknown_fields + medium_fields + provenance + temporal).
