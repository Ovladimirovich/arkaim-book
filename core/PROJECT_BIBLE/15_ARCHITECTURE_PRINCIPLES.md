# 15_ARCHITECTURE_PRINCIPLES.md

## Конституция проекта

---

## Принцип 1: Книга — первичный источник истины
Книга является единственным первичным источником знаний о произведении. Все остальные документы (синопсис, заметки, интервью) — вторичные источники. При противоречиях приоритет всегда у книги.

## Принцип 2: Повествование — финальная инстанция
Система не заменяет повествование и не переписывает его. Любое внешнее действие (публикация, рассылка, ответ читателю) требует подтверждения.

## Принцип 3: Понимание предшествует автоматизации
Никакие автоматические процессы (генерация, публикация, интеграции) не начинаются, пока система не пройдёт этап BOOK INTELLIGENCE — способности самостоятельно отвечать на вопросы о книге.

## Принцип 4: LLM — инструмент, не архитектура
Архитектура проектируется независимо от конкретной LLM-модели. LLM используется только как инструмент анализа и генерации. При смене провайдера меняется только адаптер.

## Принцип 5: Данные — главный актив проекта
Код может быть переписан. Данные — нет. Поэтому формат данных (JSON-схемы, структура БД) проектируется с запасом прочности и версионируется.

## Принцип 6: Один объект — одна ответственность
Каждый модуль решает одну задачу. Reader читает, Understanding понимает, Genome хранит, World моделирует, Intelligence отвечает, API обслуживает, UI отображает.

## Принцип 7: Сначала схема, потом данные
Никакие данные не создаются без утверждённой JSON-схемы. Сначала проектируем структуру, потом наполняем.

## Принцип 8: Простота вместо сложности
Если есть выбор между простым и сложным решением, выбираем простое, даже если второй вариант кажется «более профессиональным». Сложность добавляется только при реальной необходимости.

## Принцип 9: Версионность всего
Каждая версия книги, анализа, генома, схемы имеет уникальный идентификатор. Никакие данные не перезаписываются без явного запроса.

## Принцип 10: Документация перед кодом
Любое изменение архитектуры сначала фиксируется в документации (PROJECT_BIBLE, ADR), только потом реализуется в коде.

## Принцип 11: Автономность restricted by design
Система не имеет возможности выполнять действия без подтверждения. Автономия = 0 по умолчанию.

## Принцип 12: Одна книга одновременно
Первая версия работает только с одной книгой. Масштабирование на несколько книг — задача v2.0.

## Принцип 13: Агенты после интеллекта
Агенты, оркестрация, маршрутизация появляются только после того, как система достигнет BOOK INTELLIGENCE. Раньше — нет.

## Принцип 14: Открытость для изменений
Архитектура не зацементирована. Каждое ключевое решение фиксируется в ADR с объяснением причин. Это позволяет пересмотреть любое решение, зная, зачем оно было принято.

## Принцип 15: Human-in-the-loop forever
Человек остаётся в контуре всегда. На любом этапе можно вмешаться, скорректировать, остановить. Система — инструмент, а не автономный агент.

## Принцип 16: Авторство не раскрывается
Тема авторства, личности записавшего книгу, источников его знаний и происхождения не является предметом обсуждения, анализа или раскрытия. Система не комментирует, не расследует и не распространяет информацию об авторстве. Существует только повествование.

---

*Этот документ является конституцией проекта. Любое архитектурное решение должно соответствовать этим принципам. Если принцип нарушается — решение возвращается на доработку.*
