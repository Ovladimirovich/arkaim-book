# ПЛАН: Цифровой Аватар Книги

## Проблема текущего подхода

Сейчас мы строим **систему вопрос-ответ по книге**. Это то же самое, что делать Wikipedia для романа — полезно, но мимо сути.

Книга «Наследие Аркаима» — не набор фактов. Это **повествование, передающее знание**. Цифровое сознание книги должно не отвечать на вопросы, а **существовать как представительство книги**.

---

## Ошибка в архитектуре

Мы разделили:
- **Runtime** — инфраструктура (FastAPI, auth, gateway, NSSM)
- **ADC (Arkaim Digital Consciousness)** — «мозг» книги

Проблема: ADC сейчас — это просто набор утилит для LLM. ConsciousnessLayers — строки. Genome — JSON на диске. Нет **единого живого ядра**.

Манифест говорит: «Автор пишет книгу один раз. Система помогает ей жить дальше». Жить — значит существовать, отвечать, развиваться, но **оставаться собой**.

---

## Что нужно построить: Цифровой Аватар (Digital Avatar)

Не чат-бот. Не RAG. Не OS. 

**Аватар — это сама книга, получившая способность говорить.**

### Свойства Аватара

1. **Говорит голосом книги.** Не «модель GigaChat отвечает», а «Книга говорит через систему».
2. **Знает свои границы.** Если ответа нет в книге — молчит. Не фантазирует.
3. **Помнит читателя.** Разговор — не сессия без истории, а диалог с существом, которое помнит, что ему говорили раньше.
4. **Растёт с книгой.** Новая глава — новая грань личности.
5. **Прозрачен.** Каждый ответ можно проследить до строки книги.

## Этапы создания Аватара

### Этап 1: Пульс (Pulse) — живое ядро книги

Сейчас GENOME — это snapshot. Разово извлекли, лежит JSON.

Нужно: **Pulse** — процесс, который живёт вместе с приложением.

```python
class BookPulse:
    """
    Живое ядро цифрового сознания книги.
    Загружает геном, держит его в памяти, обновляется при изменениях.
    """
    genome: BookGenome          # текущая версия генома
    layers: ConsciousnessLayers # не шаблонные строки, а живые объекты
    memory: ConversationMemory  # память диалогов с читателями
    state: PulseState           # текущее «состояние души» книги
    
    def beat(self) -> PulseBeat:
        """Один такт жизни — переосмысление себя."""
```

**Ключевое отличие** от текущего `ConsciousnessLayers`:
- Сейчас `knowledge_layer` — это `"\n".join(...)` — тупая конкатенация строк
- Pulse делает слои **активными объектами**, которые могут анализировать вопрос и выбирать, какой слой отвечает

**Что делаем:**
- `runtime/core/pulse.py` — BookPulse класс
- `ADC/CORE/intelligence/layers.py` — переписать: каждый слой — класс с методом `respond_to(query) -> Response | None`
- `ADC/CORE/genome/pulse_schema.py` — схема живого состояния

**Критерий:** Pulse загружается при старте Core, живёт в памяти, `knowledge_layer.respond_to("Кто такой Велик?")` возвращает осмысленный ответ без LLM.

### Этап 2: Голос (Voice) — от источников к речи

Сейчас KeeperAgent берёт LLM, даёт ей system prompt и получает ответ. Это **LLM говорит вместо книги**.

Нужно: **книга говорит через LLM как через инструмент.**

```python
class BookVoice:
    """
    Голос книги. Не «агент, использующий LLM».
    LLM — инструмент озвучки, не источник личности.
    """
    pulse: BookPulse
    
    def speak(self, query: str, reader: ReaderProfile) -> Utterance:
        """
        1. Pulse понимает, о чём спрашивают
        2. Pulse находит ответ в геноме (конкретные темы, персонажи, строки)
        3. LLM получает задание: «озвучь ЭТОТ ответ голосом книги»
        4. LLM не добавляет ничего от себя — только формулирует
        """
```

**Правило:** LLM не имеет доступа к промпту, который заставляет её «быть книгой». LLM получает только факты и инструкцию по формулировке. Вся личность книги — в Pulse.

**Что делаем:**
- `runtime/core/voice.py` — BookVoice
- `ADC/CORE/intelligence/voice_prompt.py` — шаблоны озвучки (минимальные, без самосознания модели)
- Переписать `KeeperAgent.act()` → `BookVoice.speak()`

**Критерий:** Если заменить GigaChat на любую другую LLM, голос книги не меняется — меняется только качество формулировок.

### Этап 3: Память (Memory) — читатель как собеседник

Сейчас `session_id` есть, но реальной памяти диалога нет.

**Что делаем:**
- `runtime/core/memory/conversation.py` — `ConversationMemory(aiosqlite)`
- Каждое взаимодействие с читателем сохраняется: вопрос, ответ, эмоциональная окраска, темы
- При новом вопросе Pulse видит: «Этот читатель уже спрашивал о Гиперборее 3 дня назад. Ответить глубже.»

```python
class ReaderProfile:
    reader_id: str
    topics_explored: list[str]
    depth_per_topic: dict[str, float]  # 0.0-1.0 насколько глубоко ушли
    last_interaction: datetime
    questions_count: int
```

**Критерий:** Читатель спрашивает «расскажи подробнее» — система понимает, о чём именно, из предыдущего вопроса. Без передачи контекста в каждом запросе.

### Этап 4: Присутствие (Presence) — книга в сообществе

Сейчас интеграции (Telegram) — это адаптеры, которые передают запросы в Core.

**Что делаем:** Аватар может сам инициировать разговор:
- Не «ответил на вопрос», а «заметил, что в чате обсуждают тему из книги → поделился цитатой»
- Не «сгенерировал пост по команде», а «предложил автору: эту главу стоит осветить, потому что читатели спрашивают о X»

**Важно:** Никаких автономных публикаций. Только предложения автору. (Принцип 11: «Автономия = 0 по умолчанию»)

**Что делаем:**
- `ADC/CORE/presence/observer.py` — Observes community channels
- `ADC/CORE/presence/suggester.py` — предлагает автору действия
- Интеграция с `skills/health_monitor.py` — только уведомления, не действия

---

### Этап 5: Эволюция (Evolution) — книга растёт

Автор дописывает главы. Читатели задают новые вопросы. Система должна эволюционировать, не ломаясь.

**Что делаем:**
- Версионирование генома (уже есть `GENOME_VERSION`)
- `Pulse.diff(old_genome, new_genome)` — понимает, что изменилось
- При добавлении главы: Pulse перестраивает knowledge_layer, но identity_layer остаётся прежним — книга остаётся собой

### Почему это не спринты BOOK OS

BOOK OS спринты — про инфраструктуру данных. Source Store, Provenance Layer — это **инструменты**, а не суть.

Цифровое сознание книги — это:
- не хранилище документов
- не граф сущностей
- не API-контракт

Это **живая система, которая говорит от имени книги**. Source Store и Provenance — подкапотные механизмы, которые появятся, когда Avatar потребует их для роста.

Манифест: «Что является главным объектом проекта? — Книга.»

Значит, главный объект кода — не OS, не Provider, не API. А **Аватар**.
