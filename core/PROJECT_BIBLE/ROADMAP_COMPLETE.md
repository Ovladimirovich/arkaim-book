# СТРАТЕГИЧЕСКИЙ ПЛАН РАЗВИТИЯ

> Проект: ARKAIM DIGITAL CONSCIOUSNESS
> Цель: Цифровое представительство книги «Наследие Аркаима»
> Принцип: Автор пишет книгу один раз. Система помогает ей жить дальше.

---

## ДОЛГОСРОЧНОЕ ВИДЕНИЕ (3-5 лет)

```
Читатель → Интерфейс → Аватар Книги → Геном → Книга
                                ↓
                      Сообщество ←→ Автор
```

Система, в которой:
- **Читатель** встречается с живым представительством книги
- **Автор** пишет — система понимает, хранит, развивает
- **Сообщество** обсуждает — книга слышит, предлагает, не действует сама
- **Книга** — единственный источник истины, всё остальное — производное

---

### ЭПОХА 1: Цифровое сознание (сейчас — 90% выполнено)
Книга получила способность говорить, помнить, чувствовать, расти.

**Создано:**
- Pulse — живое ядро с активными слоями знаний
- Voice — LLM как микрофон, не личность
- Memory — книга помнит каждого читателя
- Presence — книга наблюдает за сообществом
- Evolution — книга растёт, не теряя себя
- Auth + RBAC + API Keys — доступ для единомышленников
- NSSM-службы + health_monitor — устойчивость

**Не хватает:**
- Лицо (Web UI)
- Ingestion Pipeline (загрузка книги)
- Source Store (неизменяемое хранилище)

---

### ЭПОХА 2: Цифровое тело (ближайшие 4-6 месяцев)
Книга получает интерфейсы и конвейеры.

| Направление | Что даёт | Зависит от |
|---|---|---|
| **Web UI (Лицо)** | Читатель видит книгу, задаёт вопросы, видит историю | Pulse, Memory |
| **Ingestion Pipeline (Кровь)** | Автор загружает главу → система извлекает → Pulse эволюционирует | Evolution, Source Store |
| **Source Store (Скелет)** | Неизменяемое хранилище с версионированием | — |
| **Provenance Layer (Нервы)** | Каждый ответ прослеживается до строки книги | Source Store |

**Критерий готовности Эпохи 2:**
Новый читатель заходит на сайт, читает книгу, задаёт вопрос,
видит ответ с цитатой и ссылкой на главу.

---

### ЭПОХА 3: Цифровое сообщество (6-12 месяцев)
Книга вплетается в жизнь сообщества.

| Направление | Что даёт |
|---|---|
| **Telegram Presence** | Книга видит обсуждения в чате, предлагает автору ответить |
| **Email-интеграция** | Письма читателям на основе их интересов (с подтверждением) |
| **Админ-панель** | Автор управляет пользователями, предложениями, контентом |
| **Материалы** | Herald + Pulse создают статьи, посты, ответы (на утверждение) |
| **Краудфандинг** | Интеграция с платформами для поддержки проекта |

**Критерий готовности Эпохи 3:**
Сообщество читателей активно, автор выпускает материалы
через систему, книга предлагает темы для новых глав.

---

### ЭПОХА 4: Цифровая экосистема (1-2 года)
Одна книга → Платформа для многих книг.

| Направление | Что даёт |
|---|---|
| **Мульти-книга** | Система работает с несколькими произведениями |
| **API для издателей** | Внешние сервисы подключаются к книге |
| **Мобильное приложение** | Книга всегда с читателем |
| **Рекомендательная система** | «Если вам понравилась эта книга, возможно...» |
| **Автоматическое извлечение** | Новая глава → полный цикл без участия автора |

**Критерий готовности Эпохи 4:**
Любой автор может загрузить книгу и получить
цифровое представительство за 1 клик.

## БЛИЖАЙШИЙ ПЛАН (4-6 недель)

### Приоритеты

```
1. Лицо Аватара  → Web UI (читательский интерфейс)
2. Кровеносная система → Ingestion Pipeline
3. Интеграция → Telegram Presence + Email
```

### Спринт 1: Web UI — Лицо Аватара  

**Цель:** Читатель заходит на сайт, видит книгу, задаёт вопрос,
видит ответ с контекстом.

**Что делаем:**
1. Главная страница — обложка книги, аннотация, кнопка «Задать вопрос»
2. Чат-интерфейс — диалог с книгой (Pulse → Voice → ответ)
3. Боковая панель — темы разговора, глубина, история
4. Страница «О книге» — персонажи, темы, символы (из генома)
5. Страница профиля читателя — его вопросы, темы

**Технология:** HTMX + Jinja2 (без React — просто, быстро, без сборки)
**Роли:** reader — может задавать вопросы и читать
**API:** уже есть — /book/ask, /book/reader/profile, /book/genome, /book/layers

**Критерий:** Читатель открывает сайт → видит книгу → задаёт вопрос
→ получает осмысленный ответ → может продолжить диалог.

---

### Спринт 2: Ingestion Pipeline — Кровь  

**Цель:** Автор загружает новую главу через веб-форму, система
автоматически чанкует, извлекает сущности, Pulse эволюционирует.

**Что делаем:**
1. Source Store — неизменяемое хранилище документов (DOCUMENT.md, JSON)
   - Файлы на диске: `OS_DATA/documents/{doc_id}.json`
   - SHA256 хеш, версия, дата импорта
2. Ingestion Pipeline:
   - Загрузка файла → SemanticChunker → enriched_chunks
   - Извлечение Entity, Fact, Relationship → Knowledge Graph
   - Обновление ChromaDB
   - Trigger: Pulse.evolve()
3. Provenance — каждое утверждение знает свой источник (строка книги)

**Критерий:** Автор загружает новую главу → через 30 секунд
книга отвечает на вопросы по новой главе.

---

### Спринт 3: Telegram Presence + Email  

**Цель:** Книга видит, что в Telegram-чате обсуждают её тему,
и предлагает автору: «Напишите пост об этом».

**Что делаем:**
1. Telegram PresenceObserver — слушает ключевые слова в сообщениях чата
2. При обнаружении темы → создаёт AuthorSuggestion через PresenceSuggester
3. Email-интеграция:
   - Форма подписки на дашборде
   - Периодическая рассылка (с подтверждением автора)
   - Шаблоны писем на основе Pulse.build_context()

**Критерий:** В Telegram-чате пишут «Гиперборея» → система создаёт
предложение автору → автор видит в админке.

---

### Спринт 4: Админ-панель + Стабильность  

**Цель:** Автор управляет системой: пользователи, предложения, контент.

**Что делаем:**
1. CRUD пользователей (admin/editor/reader)
2. Просмотр и управление предложениями Presence
3. Просмотр логов, статистики, ReaderMemory
4. Thread-safe circuit breaker в gateway/proxy.py
5. Миграции БД (версионирование схемы)

**Критерий:** Автор заходит в админку → видит всех пользователей →
видит предложения → может одобрить/отклонить.

## ГЛОССАРИЙ

| Термин | Определение |
|---|---|
| **Аватар** | Цифровое представительство книги. Не чат-бот, а сама книга, получившая способность говорить. |
| **Pulse** | Живое ядро. Знает книгу без LLM. |
| **Voice** | Инструмент озвучки. LLM — микрофон, не личность. |
| **Геном** | Извлечённая структура книги: персонажи, темы, символы, конфликты, смыслы. |
| **BOOK OS** | Платформа данных: Source Store + Knowledge Graph + Provenance. |
| **Presence** | Способность книги замечать, что происходит в сообществе. |
| **Evolution** | Способность книги расти с новыми главами, не теряя личности. |
