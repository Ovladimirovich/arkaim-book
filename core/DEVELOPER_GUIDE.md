## 1. Главный принцип

**Книга — первичный источник истины.**

Автор — финальный носитель замысла. Система — инструмент, а не замена.

**Цифровое представительство книги (Аватар) — не чат-бот. Это сама книга, получившая способность говорить.**

---

## 2. Архитектура в двух словах

```
Читатель → Web UI (Jinja2+HTMX) → Gateway :8080 → Core :8642
                                                       │
                                              ┌───────┴────────┐
                                              │    BookPulse    │
                                              │  (живое ядро)   │
                                              │ ┌─────────────┐ │
                                              │ │KnowledgeLayer│ │
                                              │ │ MeaningLayer │ │
                                              │ │IdentityLayer │ │
                                              │ │ MissionLayer │ │
                                              │ └─────────────┘ │
                                              │    BookVoice     │
                                              │  (LLM-микрофон)  │
                                              │   ReaderMemory   │
                                              │   Presence       │
                                              │   Evolution      │
                                              └─────────────────┘
```

### Ключевые понятия

- **Pulse** — знает книгу без LLM. Каждый слой может ответить на вопрос сам.
- **Voice** — LLM не личность, а микрофон. Формулирует то, что Pulse уже знает.
- **ReaderMemory** — книга помнит каждого читателя и его темы.
- **Presence** — книга «замечает», что обсуждают читатели, и предлагает автору.
- **Evolution** — книга растёт с новыми главами, не теряя себя.

---

## 3. Порядок работы

```
1. Pulse (живое ядро) ✅
2. Voice (голос книги) ✅
3. Memory (память читателя) ✅
4. Presence (присутствие) ✅
5. Evolution (рост) ✅
```

Любая новая функция должна проходить через Pulse. Не через LLM напрямую.

## 5. Версионирование

### Версии проекта: `major.minor.patch`
- major — breaking changes в архитектуре
- minor — новые функции
- patch — исправления

### Версии генома: `GENOME_v{major}.{minor}.{patch}`
- Каждая версия сохраняется в `GENOME/history/`
- Текущая — `GENOME/GENOME_v{major}.{minor}.{patch}.json`

## 6. Правила работы с LLM

### LLM — инструмент, не архитектура
- Никакие решения не принимаются на основе возможностей LLM
- Архитектура не зависит от провайдера LLM
- При смене LLM меняется только адаптер (BookVoice.set_llm())
- Личность книги — в Pulse, а не в system prompt

### Voice-протокол:
1. Pulse слушает вопрос → находит ответ в геноме
2. Если ответ найден с высокой уверенностью — Voice отвечает без LLM
3. Если уверенность низкая — LLM формулирует, Pulse проверяет
4. IdentityLayer.validate() — финальная проверка

### Промпты
- Все промпты — в `runtime/prompts/`
- Версионируются
- Не определяют личность модели — только инструкции по формулировке

## 7. Запреты

❌ Не давай LLM system prompt, который заставляет её «быть книгой» — личность только в Pulse
❌ Не создавай новый модуль, не проверив, нет ли его функционала в Pulse/layers/
❌ Не делай автономных действий (публикации, рассылки и т.д.)
❌ Не удаляй файлы без подтверждения автора
❌ Не читай книгу через код прежде, чем создашь обработчик
❌ Не подключай UI прежде, чем создашь API
❌ Не работай с личными данными без согласования

## 9. Создание нового модуля

1. Проверь, не делает ли Pulse/layers уже это
2. Создай Pydantic-схему в `schemas/`
3. Создай модуль в `ADC/CORE/` или `runtime/core/`
4. Добавь Dependency в `adc_deps.py`
5. Если нужно — API эндпоинт в `book_routes.py` или `ui_routes.py`
6. Добавь тесты
7. Обнови документацию
